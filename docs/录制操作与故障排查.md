# 录制操作与故障排查

更新：2026年10月14日。本工具仍为测试版，不保证视频号无人值守取流。

## 抖音录制

1. 按 README 安装并启动后台，打开启动时显示的本机管理页面。
2. 添加主播：平台选择抖音，填写主播名称及直播间地址，例如 https://live.douyin.com/直播间编号 。也支持分享链接中的 live_web_rid 参数。主播主页解析尚未接入。
3. 选择视频、音频或同时保存，选择360p/480p/720p；存储估算不是实际文件大小保证。
4. 开启监控。只有状态为录制中且文件持续增长，才能确认已录上；连接中不代表成功。
5. 抖音网页可以关闭，后台必须保持运行。电脑保持开机联网、不休眠。
6. 暂停监控后等待文件收尾，再回放已结束文件。

## 视频号录制

1. 启动取流代理，确认它正在运行；按照项目配置工具设置当前网络服务的系统HTTP/HTTPS代理并安装本工具CA。证书和系统授权由用户操作，不发送管理员密码。
2. 本版默认代理地址127.0.0.1，端口8899；不需要代理账号密码。避免覆盖其他网络工具设置，优先使用提供的配置与恢复流程。
3. 完整退出并重新打开电脑微信，进入直播，播放约十秒。
4. 工作台出现候选源后手动填写主播名称并添加录制。多个源不能只凭顺序认定主播，先试录核对画面。
5. 静音不等于不能取流。拿到源后后台自行连接视频流，不是录制微信窗口画面；关闭窗口后是否持续以及地址失效后的恢复仍需验证。
6. 结束时先恢复原系统代理，再停止取流代理；代理开启期间不要停止代理服务，否则可能影响联网。

## 文件在哪里

录像已在本地保存，无需下载才存在。当前原型保存在项目 outputs/live-recorder/recordings 下；打包应用默认保存在用户 Movies/直播录制 下，以工作台显示的保存位置为准。按主播和日期归档，视频MP4、音频M4A，通常30分钟分段。

正在写入的MP4可能尚不能正常打开。查看已完成分段；下载只是另存一份。主分支现有版本与本地开发版本可能不同：本地新增改名、路径显示和打开文件夹功能尚待部署验证，不能据此声称发布附件已有这些功能。

## 故障排查

| 现象 | 处理与判断 |
|---|---|
| 本机页面打不开 | 确认后台进程运行、使用启动时显示的端口；网页关闭和后台退出是不同操作。 |
| 代理运行但连接计数为零 | 核对当前网络服务HTTP/HTTPS代理开关、地址和端口。曾实测系统代理关闭导致零连接。保存配置后完整重启微信。 |
| 有代理连接但无候选源 | 检查TLS失败计数，重新进入一场直播做对照。若仍无源，需检查媒体响应格式与识别规则；不能把连接正常当成录制成功，也不要无限反复重开。 |
| 等待新地址 | 手动重新打开同一直播可能恢复原任务；这不是无人值守恢复。不要把其他主播源关联到旧任务。 |
| 长时间连接中或零字节 | 检查主播是否下播、输入地址是否有效；记录为待定位故障，不能断言正常结束。 |
| 磁盘不足 | 清理或迁移已结束录像，检查可用空间；软件有不足1GB停止新录制或暂停的保护。不要删除正在写入文件。 |
| 停代理后无法联网 | 先恢复系统代理原设置，避免保留指向已停止本机服务的代理。 |
| Mac阻止应用启动 | 当前包未完成苹果签名公证，记录具体系统提示并反馈，不把它当正式开箱即用版本。 |

## 验证标准与现状

- 抖音和视频号分别验证连续三小时，不互相替代。累计运行时间不等于无中断录制；需核对日志、每段文件、声音和画面。
- 主播提前下播应作为正常结束检查，不能算录满三小时，也不能自动认定为故障。
- 本地循环测试源能检查分段与资源，不替代平台真实取流。
- 真实断网测试单独安排：先确认持续写入，断网约一分钟再恢复，期间不重启任务，核对是否自动恢复和缺失时长；断网内容不能补录。
- 地址失效后无需人工重开或粘贴即可自动恢复，才算无人值守更新通过。目前未通过。
- 昨晚视频号连续三小时测试未通过；人工重开后恢复验证通过，已结束视频文件完整解码通过。
- 正式版仍需新机器安装、真实恢复、准确主播关联及下播判断、退出代理恢复、签名公证等验收。视频号跨场自动发现未完成。

反馈时提供平台、发生时间、界面状态、是否仍直播、系统版本和脱敏截图。不要上传密钥、Cookie、签名直播URL、代理私钥或完整抓包内容。
